# Изменение пути до endpoint

Worker читает фактический маршрут к каждому выбранному числовому endpoint через BSD routing socket (`RTM_GET`). Исходное состояние фиксируется до создания utun, повторно проверяется после адресов/routes/DNS и затем каждые две секунды. Один общий deadline на набор адресов — две секунды; максимум 16 endpoints, одинаковые IP дедуплицируются. У socket короткие read/write timeouts; число чужих сообщений и размер ответа ограничены. Нет shell, разбора локализованного route output, полного dump сети или адресов в argv/logs/public DTO.

Сравниваются interface index/name, direct/gateway routing, gateway scope и исходный IP/scope, если kernel возвращает его. Unavailable/reject/blackhole/dead routes не принимаются. ARP/NDP hardware address не является идентичностью пути. При изменении или невозможности проверки закрывается engine/utun и own temporary DNS; статус становится Error с фиксированным сообщением без адресов. Stop завершает monitor и observer; старый observer не закрывает новую session.

Run 38418166219 / source `6f001c2db3332548925445fde22f822c450ae6aa` подтвердил native RTM_GET для IPv4/IPv6 loopback, production tests/vet, прежние encrypted peers/DNS/crash/installer scenarios на Intel macOS 15.7.9. Unit tests покрывают gateway, source, interface replacement, IPv6 scope, недоступность, дедупликацию, deadline, приватность ошибок и завершение monitor. Run 38419688718 / source `90efb8b8583422f857d8b1054299b2493babb0cf`: kernel UDP probe, actual official encrypted traffic через отдельный CI-owned outer utun, затем удаление этого utun подтвердили автоматическое закрытие inner tunnel/Error, own interface cleanup и исходные маршруты. UDP reflection в test fixture ограничен constant synthetic address; ничего не имитирует в production worker. Первый fixture run 38418795435 не доставлял UDP и не считается PASS; исправление и реальное повторное испытание сохранены.

Это консервативное закрытие split session с bounded polling, не fail-closed политика. Между checks есть интервал; обычный split трафик вне AllowedIPs продолжает пользоваться исходной сетью. Не реализованы auto reconnect/backoff, полноценный sleep/wake, DNS re-resolution, captive portal или физические host escape routes. Монитор отслеживает исходные выбранные endpoint IP; authenticated engine roaming не получает отдельной гарантии. Source IP отсутствует в отдельных kernel replies, поэтому тест не доказывает обнаружение каждого DHCP/address change. Нужны live physical Wi-Fi/Ethernet/DHCP/sleep и target испытания.

Private in-memory snapshot не является durable recovery journal и не доказывает владение маршрутом. Full profiles остаются отвергнутыми до endpoint escape/verified guard/recovery. Ни системный default route, ни чужие PF правила monitor не меняет.
