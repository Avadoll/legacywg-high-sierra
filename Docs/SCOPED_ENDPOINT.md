# Scoped endpoint socket candidate

Research checkpoint 13 October 2026. Product still uses the unmodified official default Bind and rejects full tunnels. This experiment is a candidate for the endpoint escape layer, not an implemented product feature.

High Sierra-era Apple source handles socket interface binding for [IPv4 IP_BOUND_IF](https://github.com/apple-oss-distributions/xnu/blob/xnu-4570.71.2/bsd/netinet/ip_output.c) and [IPv6 IPV6_BOUND_IF](https://github.com/apple-oss-distributions/xnu/blob/xnu-4570.71.2/bsd/netinet6/ip6_output.c). This establishes an implementation reference; it is not a target runtime or API maintenance guarantee. The pinned WireGuard public `conn.Bind` interface permits transport implementations, but its default Darwin transport exposes neither the socket descriptors nor an interface binding method. No reflection, linkname, FD enumeration, vendor modification, own cryptography or replacement engine was introduced.

## Actual kernel experiment

[Run 38455001863](https://github.com/Avadoll/legacywg-high-sierra/actions/runs/38455001863), source `2b98b1cff3e1ae2334e567cec5c58d3860ccfb68`, disposable Intel `macos-15-intel` runner, pinned Go1.24.13/Xcode16.4: native cross-build/vet and actual root kernel experiment PASS.

Separate developer executable `Engine/scopedfixture` creates two owned utun interfaces and uses the pinned official netstack as a UDP echo server behind the first interface. Wildcard native UDP listeners match the default transport's local binding behavior. The bound listener applies and reads back the family-specific socket option. A test prefix has both an unscoped route and an explicit route in the first interface's scope. A more-specific host route on the second interface then competes with it. These are synthetic benchmark routes on owned virtual interfaces; no physical/default route or PF setting is changed.

Both families separately proved:

- Ordinary and bound baseline UDP round trips.
- A fresh ordinary listener loses its round trip and packets reach the second interface. The conflicting host route is confirmed selected by the ordinary kernel query.
- Four bound round trips still traverse the first interface; the second interface receives zero bound packets during that measured phase.
- Closing the first interface stops bound traffic without packets falling back to the second interface.
- Closing the second interface restores the original gateway/interface result for the synthetic destination. Final native interface name/index set matches the baseline.

Reports are sanitized and source/artifact hashes verified in `Evidence/ScopedEndpoint/38455001863`. Raw packet data, route tables and interface identities are not published. This is plaintext UDP routing evidence, not encrypted WireGuard or physical Wi-Fi/Ethernet proof.

## Remaining decision and proof

The encrypted prototype below supplies one-peer traffic and a bounded close/reopen proof for each family separately. It does not justify switching the product transport yet. The later query/admission proof below covers scoped kernel snapshots and refusal after interface loss on this virtual fixture. The subsequent observer proof below adds periodic virtual-path checks and a transport-loss latch. The later simultaneous-family two-peer proof below covers that limited topology and concurrent query correlation. Remaining work includes physical source/interface lifetime and index-reuse behavior, additional same-family/multi-interface peers, hostname/authenticated roaming/cancel behavior and measurable transport/resource performance. There is still no proof for physical gateways, existing scoped defaults, physical interface replacement/index reuse, sleep/DHCP, roaming, packet capture or High Sierra.

If the physical interface already has a usable scoped route, socket lifetime might avoid creating a persistent endpoint host route. If it does not, the product must refuse before mutation or implement and prove owned durable physical route recovery. The surrogate test explicitly adds its scoped prefix and does not establish that every physical interface has one.

PF protection, all-traffic DNS/IPv6 leak prevention, protected GUI/helper/engine crash lifetime and durable ownership remain required. Full profiles stay rejected, `protection_ready=false`, research pkg remains unsigned. No new client artifact or release approval was produced by this experiment.

## Encrypted official-device prototype

[Run 38456456242](https://github.com/Avadoll/legacywg-high-sierra/actions/runs/38456456242), exact source `640ad7331ded5f610903eec8fc7d2a70b8893a7d`, pinned Go1.24.13 on Intel macos-15-intel: native build/vet and experiment PASS. The dedicated report does not export an OS patch version. Evidence and verified source/artifact hashes are in `Evidence/ScopedEndpoint/38456456242`.

The separate fixture implements the exported `conn.Bind` contract with a thin packet adapter. Official device, crypto, endpoint and netstack sources remain unmodified. The client uses a wildcard native UDP socket with the family-specific interface binding option; the peer lives in the official netstack behind an owned kernel utun. Two official encrypted devices and an inner UDP echo are exercised for IPv4 and IPv6 separately. Ephemeral keys are generated locally, core dumps disabled, UAPI never exported and loggers silent.

Each family completed six encrypted round trips: one baseline, four with a competing host route on the second owned interface, one after actual official Device.Down/Up reopened the bound transport. Both devices reported nonzero authenticated handshake timestamp and RX/TX counters. Zero packets for the endpoint reached the second interface during the encrypted phase. A separate callback lease check confirmed the old receive function remains closed after a new socket opens. Closing the first interface prevented further plain and encrypted round trips with zero fallback packets on the second interface. Synthetic destination gateway/interface and the native interface name/index set returned to baseline.

This still requires an explicit synthetic scoped prefix. It is one-peer sequential-family virtual-topology evidence. It does not prove physical Wi-Fi/Ethernet, a usable existing physical scoped route, simultaneous dual-stack, multi-peer/hostname/roaming, interface index reuse, scoped BSD query/lifetime enforcement, DHCP/sleep, transport process crash, resource/performance or High Sierra. The adapter is developer-only, excluded from app/pkg. Product transport is unchanged, `protection_ready=false`; no new client artifact was generated.

## Scoped kernel query and socket admission

[Run 38458097751](https://github.com/Avadoll/legacywg-high-sierra/actions/runs/38458097751), exact source `25c89ed311fa5b120733d64755904c410330fcc0`: pinned native build/vet and the extended IPv4/IPv6 encrypted experiment PASS. Source/artifact/report SHA verified in `Evidence/ScopedEndpoint/38458097751`. The client app/pkg remain the previous tested d32a5a5/run38451987993.

The developer observer sends read-only BSD `RTM_GET` with `RTF_IFSCOPE` and `rtm_index`, following [Apple's pinned High Sierra-era routing socket implementation](https://github.com/apple-oss-distributions/xnu/blob/xnu-4570.71.2/bsd/net/rtsock.c). Its private socket has 100ms I/O timeouts, a caller deadline and independent two-second limit, at most 128 reads and a 64KiB buffer. Unmatched messages are skipped; invalid/error/reject/blackhole/dead replies and an unexpected interface index are refused. No full routing table or interface metadata is exported.

For each family the actual unscoped kernel query selected the competing interface while the scoped query retained the captured original interface/source/gateway identity. The socket factory checks that exact scoped snapshot, interface index/name/UP and current local address membership before and after opening; failure closes a newly opened socket. This prototype conservatively requires the returned route to carry `RTF_IFSCOPE`; it does not yet admit potentially usable implicit primary routes. Canceled queries and a deliberately wrong interface name were refused. The complete six-echo official encrypted test, actual Down/Up reopen, old callback closure and zero decoy packets also passed with these checks enabled.

After the original interface closed, the scoped query refused its path. Actual official Device.Down followed by Device.Up returned an error and the successful-open counter did not increase. Route/interface baseline restoration passed. This is refusal at tested admission points, not atomic compare-and-open, continuous monitoring or a lifetime guarantee: network changes can happen between observations. Synthetic mismatched-name rejection does not prove actual interface index reuse; address membership is not a DHCP-generation identity. Physical gateway/default availability, route withdrawal while the interface remains up, concurrent changes/reuse, sleep/roaming, simultaneous dual-stack/multi-peer and High Sierra remain untested. No product path monitor, guard, default route or installer changed.

## Route withdrawal while the interface remains up

[Run 38459104760](https://github.com/Avadoll/legacywg-high-sierra/actions/runs/38459104760), source `b3973d79fea1b417fbfc9c4a1f4c8e3f1a6d749b`: native Intel macOS build/vet and the extended encrypted fixture PASS. Verified report/source/artifact hashes in `Evidence/ScopedEndpoint/38459104760`. No product source, app or installer changed.

The developer fixture now polls its exact admitted path every 200ms with bounded kernel queries. Upon detecting loss it atomically latches the Bind as refused and calls the actual official Device.Down, closing its lease/receive callbacks. Open checks the latch before/after socket creation; Send refuses a latched transport. The latch persists for that transport even if the path returns. The poller joins on cancellation/loss; this is neither an atomic path lifetime guard nor packet-level fail-closed protection.

The test deletes only the exact explicit synthetic scoped prefix on its owned utun and confirms the original interface index remains UP. The ordinary prefix and competing host route remain. The observer stopped the official device after 121ms for IPv4 and 133ms for IPv6, measured from before the fixed route deletion command to completion of Device.Down. A concurrent inner encrypted payload probe during this interval returned no echo; the second interface received zero endpoint packets across this measured window. After detected loss another encrypted echo failed, and official Up returned an error without increasing successful-open count. Observer completion/join passed.

Restoring the exact owned scoped prefix made the original path admissible again but could not revive the old latched transport. Closing the old two-device fixture and creating a fresh admission context produced a new official handshake/counters and encrypted echo. Each family completed seven successful encrypted round trips in total. Original conflict/reopen/callback/interface-loss/no-fallback and final route/interface baseline checks also passed.

These are single-run timings, not a maximum detection latency or zero-delay guarantee. The test intentionally permits and records an echo before detection rather than deriving a general block guarantee from polling; this run observed none. It does not establish behavior during physical gateway/DHCP/index-reuse changes, simultaneous dual-stack/multi-peer/roaming, sleep, process crash or High Sierra. Product endpoint monitor remains its existing unscoped two-second observer; production scoped transport and PF protection are not implemented.

## One simultaneous IPv4/IPv6 client with two independent peers

[Run 38460791748](https://github.com/Avadoll/legacywg-high-sierra/actions/runs/38460791748), source `9321994d813c9bcf47d058b073fdf123d5103d57`: native pinned build/vet and extended fixture PASS. Sanitized, source/artifact/report-verified evidence in `Evidence/ScopedEndpoint/38460791748`. Earlier run38460485251/source981d14e60d6595591a38ead8e9864629485c4dc4 also passed the encrypted two-peer topology; it is retained but predates the concurrency correlation fix and stress check.

The developer dual Bind opens an admitted IPv4 native socket and an admitted IPv6 native socket on the same local port, returns their separate lease-bound receive callbacks, and selects a sender by endpoint family. Both families are required in this prototype. Failure opening the second family closes the actual first native socket and exposes neither callbacks nor a port. A closed old receive callback for either family remains closed after new sockets open. The adapter has BatchSize1, refuses nonzero marks and never uses vendor changes or custom crypto.

A single official client device has two disjoint peers, one with a numeric IPv4 outer endpoint and IPv4 inner payload, one with a numeric IPv6 outer endpoint and IPv6 inner payload. Two independent official server devices reside behind one owned kernel utun/official netstack with both synthetic scoped prefixes. Concurrent inner UDP echoes and individually nonzero handshake/RX/TX on each client peer and each server are required. Ordinary fresh UDP negative controls and unscoped kernel queries confirm both conflicting host routes on the second owned interface; both scoped snapshots stay admitted. Seven successful encrypted echoes per peer cover baseline, four conflict rounds, actual Device.Down/Up of both family sockets and a fresh-context restart. The measured encrypted phases deliver zero endpoint packets to the competing interface in either family.

Withdrawing only the IPv4 scoped prefix leaves the interface UP and the IPv6 scoped path admissible. Its observer calls the actual client Device.Down: both native leases close and neither peer can echo a fresh payload after detected loss. Up refuses without another successful dual open. Restoring the route cannot revive the old context; closing it and creating a fresh context restores encrypted traffic to both peers. Both observer goroutines join on cleanup and original gateway/interface results and final interface set are restored.

Concurrency correction: [Apple's pinned routing socket source](https://github.com/apple-oss-distributions/xnu/blob/xnu-4570.71.2/bsd/net/rtsock.c) distributes route messages through raw input; private AF_ROUTE sockets must still correlate their replies. The old developer query reused PID/Seq1 and could accept another simultaneous query's reply. Each query now allocates a process-unique positive sequence and refuses exhaustion rather than reusing one. Sixty-four concurrent scoped/unscoped IPv4/IPv6 queries returned the expected paths; 9 messages for other queries from this process were observed and ignored. This corrects a static concurrency risk; the preceding successful run did not demonstrate a failure and does not contain this stress proof. The production unscoped observer was not modified.

Limits: one shared outer interface, two peers with different endpoint families, synthetic explicit scoped routes and small UDP payloads. Other same-family peers, multiple physical interfaces, hostname/authenticated roaming policy, dual-family port collision retries, batching/performance, resource/fuzz/crash/sleep/index-reuse, physical packet capture and High Sierra remain unproven. Loss polling remains experimental200ms, not packet-level protection. No transport integration into the app, new client/pkg, full routes or PF guard; `protection_ready=false`.
