# PF: исследование возможности защиты

Read-only CI run 38406580921, source 1b290edf742ab4c213afdfe5cb56514290d2f2eb, Intel macOS 15.7.9: PF был отключён, state table пуст, root rules содержали wildcard filter anchor com.apple/*, quick pass rules не найдены. Повторное чтение подтвердило прежний hash root rules. Probe не включал PF, не загружал anchor, не удалял правила или states. Экспортированы только hashes/counts, без чужих endpoint addresses/anchor names.

Это предпосылки для эксперимента на конкретном CI host, не доказательство kill switch или High Sierra. Пустая state table не проверяет поведение существующих TCP/UDP flows. В production UI защита всего трафика пока отсутствует, full profiles отклоняются.

Apple прямо описывает PF как механизм для системных служб и администраторов, а не публичный API массового продукта; возможны конфликты с системными/сторонними правилами. Рекомендуемый поддерживаемый путь — Network Extension. Для нашего legacy target это архитектурный риск, а не разрешение молча изменить backend или заявить совместимость: [TN3165](https://developer.apple.com/documentation/technotes/tn3165-packet-filter-is-not-api). Доступность и способ поставки NE на 10.13 требуют отдельной проверки.

До интеграции guard обязательны durable owned recovery journal, проверка root anchor ordering/foreign quick rules, семантики PF enable references, уже открытых states, реальный physical packet capture IPv4/IPv6/DNS, crash/GUI loss/helper recovery и отказ при несовместимой политике. Нельзя загружать global ruleset, выключать чужой firewall или обещать fail-closed по одной строке pfctl.

## Scoped egress / existing UDP state

[Run 38435625975](https://github.com/Avadoll/legacywg-high-sierra/actions/runs/38435625975), source `62bebb317f7769745d444e6e2c0847ab818e2a02`, Intel macOS15.7.9: developer-only scoped PF experiment PASS, **protection_ready=false**. На guest egress Ethernet NIC до изменения PF захвачены 4 warm и 4 fresh synthetic IPv4 UDP packets. После warm keep-state pass и замены собственным quick block старый UDP flow передал ещё 4 packets, fresh flow — 0; native block counter — 5. Это фактическое доказательство обхода нового block существующим состоянием PF, а не доказательство kill switch.

Две ссылки включения принадлежат тесту. После освобождения одной PF и scoped block сохранялись; после удаления только собственного anchor и освобождения последней обычная synthetic egress отправка вернулась, PF Disabled. Root/recursive filter/NAT text и global timeouts/memory limits не изменились. Global load/flush/disable и state kill не использовались. После освобождения references осталось одно созданное тестом UDP state; его удаление/expiry НЕ проверены. Поэтому `owned_cleanup=PASS` относится только к own rule/reference removal, не к полному восстановлению state table.

Experiment меняет только random `com.apple/legacywg-ci-<128-bit-id>` child existing wildcard и fixed synthetic benchmark ports; не создаёт endpoint host routes. Root-only developer recovery file хранит anchor/token/rule hashes, не принимает caller paths/rules/endpoints и не является production journal. Он не доказывает atomic token acquisition/commit crash recovery: unconfirmed token/changed rules требуют отказа без global fallback. Raw packet captures, interface/address metadata, PF tokens и чужие rule text не экспортируются. Test script работает только на disposable root GitHub macOS CI и не вызывается установленным приложением.

Established TCP, IPv6, DNS leak policy, foreign quick-anchor coexistence, crash/power loss/reboot, High Sierra и actual physical Mac NOT_RUN. Guest Ethernet egress capture не является испытанием физического устройства пользователя. До protected integration обязательны доказанная политика существующих states без удаления чужих, typed durable ownership/rollback, endpoint escape и полная packet-capture matrix. Full profiles продолжают отклоняться.

Разбор failed runs: 38434189215/38434522894 отказались до изменения PF из-за строгого parsing default scrub/recursive anchor display; default scrub text восстановлен из known template и его SHA256 совпал с native evidence. 38434670298/38435088264 остановились до включения PF: baseline control требовал три packets, native ICMP errors оставляли два. Fixture теперь делает пять attempts и всё ещё требует минимум три фактически captured control packets; отсутствующий peer не заменён третьей стороной. 38435369508 остановился на неверном read-only option `-s limits`; исправлено на native `-s memory`. Все failed reports сохранены и не считаются successful guard tests.

Поведение согласуется с pinned Apple XNU [pf.c](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/net/pf.c): сначала выполняется lookup UDP state, при pass используется старое rule; новый ruleset проверяется при отсутствии state. [pf_ioctl.c](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/net/pf_ioctl.c) выделяет отдельные enable tokens; release собственного token не эквивалентен global stop. Исходники не являются API compatibility guarantee для High Sierra.
