# Журнал собственного utun

Схема v1 охватывает только ephemeral utun и факт запроса temporary DNS session. Это часть восстановления, а не журнал physical endpoint routes или PF. Full profiles и kill switch по-прежнему не включаются.

Перед созданием utun worker сохраняет intent, затем identity созданного интерфейса и configured checkpoint. В запись входят версия, случайный transaction ID, boot session UUID, PID, фаза, utun name/index и DNS boolean. Ключей, профиля, IP, DNS адресов, endpoint, shell commands, произвольных путей и PF tokens нет. Boot UUID остаётся в root-only локальном файле и не экспортируется в status/diagnostics.

Фиксированный каталог `/Library/Application Support/LegacyWG/State` открывается по компонентам с `O_NOFOLLOW`. State root-owned 0700; lock и journal — regular root-owned 0600, без дополнительных hard links и ACL. Native component читает ACL уже открытого inode через `fstatx_np` и `filesec_query_property`; permission bits недостаточно. Lock inode сохраняется между sessions; `flock` запрещает параллельного writer. Temporary record создаётся exclusively, запись синхронизируется `fsync`/`F_FULLFSYNC`, затем atomic rename и directory sync. Неизвестная версия, лишние/дублированные поля, частичная запись или конфликт identity сохраняются и требуют внимания.

Recovery сначала проверяет оба fixed record files, затем удаляет только собственные документы. На том же boot живой PID или исходный utun instance запрещает recovery. При исчезновении старого интерфейса или смене boot документ можно убрать. Same-name/different-index interface считается чужим: recovery не удаляет его. Ни kernel routes, ни DNS preferences, ни PF rules/references, ни процессы по journal не удаляются. Interface-bound routes исчезают с utun; temporary DNS session сохраняет прежнюю модель process lifetime/heartbeat. Это не подтверждение отсутствия утечек.

Native tests используют root-owned TempDir и собственные disposable utun. Проверяются lock, права, ACL, symlink/hardlink/FIFO, corrupted schema, conflicting records, live/reused interface, FD closure и SIGKILL в пяти точках: temporary created, temporary synced, renamed, directory synced, live utun. Power loss, reboot, High Sierra и journal persistent changes пока не проверены. Root tests должны иметь actual PASS; non-root skip не считается доказательством.

В проверке метаданных отдельно различаются успешное чтение с отсутствующим ACL, присутствующий ACL и ошибка API/дескриптора. Native root fixture добавляет ACL к своему TempDir, проверяет отказ и удаляет ACL только у этого собственного fixture. Семантика API сверена с Apple [statx_np.c](https://github.com/apple-oss-distributions/Libc/blob/main/sys/statx_np.c) и [filesec.c](https://github.com/apple-oss-distributions/Libc/blob/main/gen/filesec.c); изучение исходников не заменяет runtime проверку целевой ОС.

## Startup и явное восстановление

Private worker при запуске вызывает Reconcile до обработки первого status. Проверка чистого состояния не создаёт каталог State, intent или интерфейс. Ошибка фиксирует RecoveryRequired и блокирует Start ещё до parsing/resolution. Helper запускает проверенный idle worker для status и повторно проверяет component pins перед Start/Recover. Recover не отключает активный VPN: сначала требуется Disconnect. Stop/Recover подтверждают Disconnected только после успешной проверки восстановления.

GUI обрабатывает status даже при ошибке операции, показывает «Нужно восстановление сети» и кнопку «Восстановить сеть…». Перед Recover есть подтверждение возврата обычной сети, перед Quit с unresolved recovery — предупреждение. Неизвестный/отсутствующий status блокирует Connect и показывает неподтверждённое состояние. Corrupt/unknown record не удаляется автоматически и не имеет force-delete команды. Удаление созданного тестом corrupted fixture — teardown developer test, не поведение продукта.
